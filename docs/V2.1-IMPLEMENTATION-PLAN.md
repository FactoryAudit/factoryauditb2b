## 0. 先看这里：需要你拍板的 6 件事

| # | 决策点 | 我的推荐 | 为什么 | 不这么做的后果 |
|---|--------|----------|--------|----------------|
| 1 | **收款主体**（P0 阻塞） | 先告诉我你用什么主体开 Stripe | Stripe 不支持中国大陆个人主体。没有合规主体 = 收不到钱 = 整个会员墙白做 | 代码写完但收款账户开不出来，M4 里程碑卡死 |
| 2 | **支付方式** | Phase 1 只做 Stripe 卡支付，支付宝延到 Phase 3 | 支付宝国际/Stripe-alipay 都需要企业资质 + 单独签约，会拖慢 2–3 周 | 首版上线时间翻倍 |
| 3 | **登录方式** | **邮箱 + 密码**（不做 Google OAuth、不做 magic link） | 邮箱密码最简单可控、不依赖第三方；magic link 依赖邮件送达（我们 Resend 域名还没验证，会 403） | 用 magic link = 用户收不到邮件 = 注册漏斗直接归零 |
| 4 | **免费额度** | 保持 `FREE_PROFILE_LIMIT = 5`/月，登录后按**去重 profile 计数**（不是按 pageview） | 按 PV 计数用户会骂人；去重计数更合理且实现简单 | 额度一个月就被点光，逼付费太早 |
| 5 | **会员墙强度** | **软锁**（SEO 内容全公开，只锁"证据明细 / 验货历史 / 风险拆解 / 完整供应商库筛选导出"） | 硬锁（整页墙）会让 Googlebot 抓不到内容，SEO 直接崩；软锁既保 SEO 又有付费理由 | 硬锁 = 我们现在几十个已收录页面全部掉出索引 |
| 6 | **Admin 后台范围** | Phase 1 只做**只读看板 + 供应商编辑 + RFQ 状态流转**，不做复杂 CRM | 你要的是"安心去开发客户"，不是再造一个 SaaS | 后台做太大，上线再拖一个月 |

**如果 6 项你没有异议，回复「按推荐执行」即可，我直接进 Phase 2。**

## 5. Existing Supplier Architecture（现有供应商架构）

### 5.1 三层访问模型**已存在**（`lib/suppliers.ts`，64 行）

```ts
export type AccessLayer = "public" | "free" | "paid";

PUBLIC_FIELDS = [legalName, country, city, industry, mainProducts, capabilities,
                 verificationStatus, riskScore, evidenceCount, lastChecked, businessType]  // 11 个
FREE_FIELDS   = [established, employees, exportMarkets, certifications, auditStatus]       // 5 个
PAID_FIELDS   = [evidence, inspectionHistory, riskBreakdown]                               // 3 个

FREE_PROFILE_LIMIT = 5      // 免费用户每月可看 profile 数
MEMBERSHIP_PRICE_USD = 99   // 单一事实来源，全站改价只改这里
MEMBERSHIP_PERIOD = "year"
```

**这是 V2.1 最值钱的遗产**：分层字段清单已经定义好了，V2.1 不需要重新设计，只需要**把它从"常量声明"升级为"运行时真的生效"**。

### 5.2 现在"锁"是怎么实现的（**假的**）

`app/[locale]/suppliers/[slug]/page.tsx` 第 261/267/314/330/341 行：

```tsx
<span className="text-[#94a3b8]">🔒</span>
<Link href={p("/register")}>{sp.freeLockCta}</Link>
```

**真相**：这些 🔒 是**硬编码的装饰**，页面根本不判断用户身份——游客和付费用户看到的 HTML 完全一样，所有区块都是"锁着"的。字段值（如 `inspectionHistory: 42`）实际上**根本没有渲染出来**，只是画了个锁图标。

**这既是坏消息也是好消息**：
- 坏消息：现在没有任何真实的权限控制
- 好消息：`established` / `employees` / `exportMarkets` / `certifications` 这些 FREE 字段目前**也没渲染**，所以 V2.1 解锁后是真的"多了新内容"，不是"把已有内容藏起来"——**付费理由成立，且不违反"不删除现有功能"**

### 5.3 读取层（`lib/queries.ts`，157 行）

```ts
listSupplierDirectory()     → SupplierView[]（按 riskScore 降序）
getSupplierDetail(slug, locale) → SupplierView + evidence + capabilities
listSuppliers()  getSupplierBySlug()  listSupplierSlugs()
listSuppliersByCountry()  listSuppliersByIndustry()  listSuppliersByAuditType()
```

> **V2.1 迁移策略**：这 7 个函数的**签名一个都不改**，只把内部实现从 `STATIC_SUPPLIERS.find()` 换成 Supabase 查询。所有消费方（页面 / sitemap / API）零改动。这正是当初"保留函数签名"设计的回报。

## 7. Required Database Tables（需建的表）

**8 张表（比 PRD 的 9 张少 1 张：把 `admin_users` 合并进 `profiles.role`）**

```sql
-- 1. profiles：用户档案（Supabase Auth 的 public 影子表）
profiles (
  id            uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  email         text NOT NULL,
  full_name     text,
  company       text,
  role          text NOT NULL DEFAULT 'buyer'   -- 'buyer' | 'supplier' | 'admin'
  locale        text DEFAULT 'en',
  created_at    timestamptz DEFAULT now()
)

-- 2. memberships：会员订阅状态（Stripe 是真值来源，本表是投影）
memberships (
  id                      uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id                 uuid NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  plan                    text NOT NULL DEFAULT 'free',      -- 'free' | 'founding_buyer'
  status                  text NOT NULL DEFAULT 'active',    -- 'active'|'canceled'|'past_due'|'expired'
  stripe_customer_id      text UNIQUE,
  stripe_subscription_id  text UNIQUE,
  current_period_start    timestamptz,
  current_period_end      timestamptz,
  created_at              timestamptz DEFAULT now()
)

-- 3. suppliers：供应商主表（从 STATIC_SUPPLIERS 迁移，slug 原样保留）
suppliers (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  slug                text UNIQUE NOT NULL,        -- ★ 必须与现有 4 个 slug 完全一致
  legal_name          text NOT NULL,
  country_code        text NOT NULL,
  city                text NOT NULL,
  industry_code       text,
  business_type       text,
  established         int,
  employees           text,
  main_products       text[],
  export_markets      text[],
  verification_status text,
  risk_score          int,                          -- 高分 = 低风险（与 lib/riskEngine 一致）
  certifications      text[],
  audit_status        text,
  inspection_history  int DEFAULT 0,
  risk_breakdown      jsonb,                        -- paid 层：8 维拆解
  access_tier         text NOT NULL DEFAULT 'public', -- 'public' | 'free' | 'paid'
  is_published        boolean NOT NULL DEFAULT true,
  created_at          timestamptz DEFAULT now(),
  updated_at          timestamptz DEFAULT now()
)

-- 4. supplier_capabilities：能力标签
supplier_capabilities (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  supplier_id uuid NOT NULL REFERENCES suppliers(id) ON DELETE CASCADE,
  ref_type    text NOT NULL,   -- 'AUDIT_TYPE' | 'STANDARD' | 'TAXONOMY'
  ref_code    text NOT NULL,
  verified    boolean NOT NULL DEFAULT false,
  source      text             -- 'Third Party' | 'Self-Reported'
)

-- 5. supplier_evidence：证据记录
supplier_evidence (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  supplier_id uuid NOT NULL REFERENCES suppliers(id) ON DELETE CASCADE,
  type        text NOT NULL,
  status      text NOT NULL,   -- VERIFIED | PENDING | UNVERIFIED | REJECTED
  source      text,
  date        date,
  note        text,
  visibility  text NOT NULL DEFAULT 'public'  -- 'public' | 'paid'
)

-- 6. saved_suppliers：收藏
saved_suppliers (
  user_id     uuid NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  supplier_id uuid NOT NULL REFERENCES suppliers(id) ON DELETE CASCADE,
  created_at  timestamptz DEFAULT now(),
  PRIMARY KEY (user_id, supplier_id)
)

-- 7. profile_views：免费额度计数（去重计数，不是 PV）
profile_views (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  supplier_id uuid NOT NULL REFERENCES suppliers(id) ON DELETE CASCADE,
  period_month date NOT NULL,   -- 当月 1 号，用于按月重置额度
  created_at  timestamptz DEFAULT now()
)
-- 唯一索引保证去重：同一用户同月同一供应商只记一次
CREATE UNIQUE INDEX profile_views_dedup ON profile_views(user_id, supplier_id, period_month);

-- 8. rfqs + rfq_matches：询价单与匹配
rfqs (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  reference_id text UNIQUE NOT NULL,     -- 对外展示用短号（RFQ-XXXXXX）
  user_id      uuid REFERENCES profiles(id) ON DELETE SET NULL,  -- 游客可为空
  company      text,
  email        text NOT NULL,
  product      text NOT NULL,
  quantity     text,
  country      text,
  message      text,
  status       text NOT NULL DEFAULT 'new',  -- new|reviewing|matched|closed
  created_at   timestamptz DEFAULT now()
)
rfq_matches (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  rfq_id     uuid NOT NULL REFERENCES rfqs(id) ON DELETE CASCADE,
  supplier_id uuid NOT NULL REFERENCES suppliers(id) ON DELETE CASCADE,
  note       text,
  status     text NOT NULL DEFAULT 'suggested',  -- suggested|contacted|won|lost
  created_at timestamptz DEFAULT now()
)
```

**不建 `comparisons` 表**：供应商对比是纯前端状态，V2.1 存 `localStorage`，登录后可同步（Phase 3 再说）。

### ⭐ `UnlockGate` 为什么必须是客户端组件（本方案最核心的设计决策）

```tsx
// 用法：服务端把"值"和"所需层级"都传进来，客户端按 tier 决定显示
<UnlockGate requires="paid" value={s.inspectionHistory} fallback={<LockIcon />} />
```

**工作方式**：
1. 服务端渲染时输出 `fallback`（锁定态），**不输出真实值** → 游客 HTML 里没有付费内容，SEO 页面也保持 **● SSG**
2. hydration 后 `AuthProvider` 拿到 `/api/me`，若 tier 足够 → 用 `value` 替换 fallback
3. 付费用户看到真实值，游客看到锁

**为什么不用服务端判断（`cookies()`）**：
- 会让 `/suppliers/[slug]` 从 **● SSG 退化为 ƒ Dynamic**（实测当前是 ●，见 §14）
- Cloudflare 缓存可能把"已解锁 HTML"发给游客（**CDN 串号**，P0 事故）
- 失去静态预渲染 = 首屏变慢 + 每次请求打 Supabase

**代价**：已登录用户会看到一瞬间的锁定态（<300ms）。可接受。

### 12.2 结账流程

```
用户点 "Become a Founding Buyer" (/membership)
    ↓ POST /api/stripe/checkout
服务端：
  ├─ 校验登录（未登录 → 带 returnTo 跳 /login）
  ├─ 查/建 stripe_customer_id（存 memberships）
  └─ stripe.checkout.sessions.create({
       mode: 'subscription',
       line_items: [{ price: STRIPE_PRICE_ID_FOUNDING_BUYER, quantity: 1 }],
       success_url: `${SITE}/account?checkout=success`,
       cancel_url:  `${SITE}/membership?checkout=cancelled`,
       client_reference_id: user.id,     ← 关键：webhook 靠它回写用户

     })
    ↓ 302 跳转 Stripe 托管页
用户付款 → Stripe 重定向回 /account?checkout=success
    ↓ 同时（异步）Stripe POST /api/stripe/webhook
```

### 12.3 Webhook 必须处理的 4 个事件

| 事件 | 处理 |
|------|------|
| `checkout.session.completed` | 用 `client_reference_id` 定位用户 → 写 `stripe_customer_id` / `stripe_subscription_id`，plan 置 `founding_buyer` |
| `customer.subscription.updated` | 同步 `status` / `current_period_end`（降级、续期） |
| `customer.subscription.deleted` | plan 回落 `free`，status = `canceled` |
| `invoice.payment_failed` | status = `past_due`，发邮件催付 |

**Webhook 硬约束**：
```ts
export const runtime = "nodejs";        // 必须，edge 下 Stripe SDK 验签不稳
export const dynamic = "force-dynamic";

const sig = req.headers.get("stripe-signature")!;
const rawBody = await req.text();        // ★ 必须先拿 raw body，不能 req.json()
const event = stripe.webhooks.constructEvent(rawBody, sig, STRIPE_WEBHOOK_SECRET);
```
- **幂等**：用 `event.id` 做去重（建 `stripe_events` 表或在 webhook 里 upsert），Stripe 会重复投递
- **返回 200 要快**：失败处理放 `waitUntil`，否则 Stripe 重试风暴
- **本地调试**：`stripe listen --forward-to localhost:3000/api/stripe/webhook`

## 15. Security / RLS Plan（安全与行级权限）

### 15.1 纵深防御三层

```
第 1 层：Cloudflare（WAF / DDoS）                    ← 已有
第 2 层：应用层字段裁剪（lib/access.ts）              ← ★ 主力
第 3 层：Postgres RLS                                 ← 兜底
```

### 15.2 应用层裁剪为什么是主力

服务端统一用 `SUPABASE_SERVICE_ROLE_KEY` 读全量数据，然后由 `lib/access.ts` 按 tier **裁剪掉不该看的字段**再返回给客户端。这样：
- **HTML 里绝对不会出现 paid 字段**（因为压根没渲染）
- 不依赖 RLS 的列级能力（Postgres RLS 做不到列级，只能靠 VIEW，成本高）

### 15.3 RLS 策略（兜底，防 anon key 直连）

```sql
-- profiles：只能看自己；admin 看全部
CREATE POLICY p_profiles_self ON profiles
  FOR SELECT USING (auth.uid() = id);
CREATE POLICY p_profiles_admin ON profiles
  FOR ALL USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));

-- memberships：只能看自己的订阅
CREATE POLICY p_memberships_self ON memberships
  FOR SELECT USING (auth.uid() = user_id);

-- suppliers：所有人可读已发布的（应用层再裁剪字段）
CREATE POLICY p_suppliers_public ON suppliers
  FOR SELECT USING (is_published = true);
-- 写操作仅 admin
CREATE POLICY p_suppliers_admin ON suppliers
  FOR ALL USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role='admin'));

-- supplier_evidence：public 可见，paid 由应用层控制
CREATE POLICY p_evidence_public ON supplier_evidence
  FOR SELECT USING (visibility = 'public');

-- saved_suppliers / profile_views / rfqs：只能操作自己的
CREATE POLICY p_saved_self ON saved_suppliers
  FOR ALL USING (auth.uid() = user_id);
CREATE POLICY p_views_self ON profile_views
  FOR ALL USING (auth.uid() = user_id);
CREATE POLICY p_rfqs_self ON rfqs
  FOR SELECT USING (auth.uid() = user_id);
-- 游客可 INSERT rfq（user_id 为 null）
CREATE POLICY p_rfqs_anon_insert ON rfqs
  FOR INSERT WITH CHECK (true);

-- rfq_matches：仅 admin
CREATE POLICY p_matches_admin ON rfq_matches
  FOR ALL USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role='admin'));
```

### 15.4 其他安全措施

| 项 | 做法 |
|----|------|
| 密码 | Supabase Auth 托管（bcrypt），**我们自己绝不碰明文密码** |
| 会话 | `@supabase/ssr` Cookie，`httpOnly` + `secure` + `sameSite=lax` |
| 邮箱枚举 | 登录/注册错误统一返回「邮箱或密码不正确」，不区分 |
| 限流 | 全部新 API 复用 `lib/rateLimit.ts`（内存 + fail-open） |
| 管理后台 | 非 admin 返回 **404 而非 401**（不暴露后台存在） |
| PII | 新增埋点事件**严禁带 email / 公司名**（`lib/analytics.ts` 的 `sanitizeParams` 已有三层防护，直接受益） |
| Service Role Key | 只出现在 Workers secrets，`git grep SUPABASE_SERVICE_ROLE_KEY` 必须只在 `.env.example` 里命中 |

| `stripe` (Node SDK) | 官方支持 Workers（基于 fetch） | ✅ 可运行 |
| `pg` / Prisma TCP 直连 | Workers **无裸 TCP socket** | ❌ **不可用** —— 所以必须用 supabase-js，不能用 Prisma |

> **这正是选型 Supabase（而不是 Neon + Prisma）的决定性理由**：Supabase 走 HTTPS/PostgREST，Workers 能吃；Neon/Prisma 走 TCP，Workers 吃不下（除非套 Hyperdrive，多一层成本与复杂度）。

## 结论

**这套方案的核心思路就一句话：不推翻 V2.0，只做加法。**

- 已有的 33 个路由段、9 条 API、9 语 i18n、SEO 矩阵、Analytics、邮件、Sheets CRM —— **一个都不删**
- `lib/queries.ts` 的 7 个函数签名**一个都不改**，只换内部实现 → 迁移风险集中在 1 个文件
- `lib/suppliers.ts` 已经定义好的 public/free/paid 三层字段清单**直接复用** → 不用重新设计权限模型
- 会员墙用**客户端软锁**（`UnlockGate`）而不是服务端硬锁 → **保住 `● SSG` 预渲染，SEO 零损失**
- `USE_STATIC_FALLBACK` 开关 → Supabase 挂了 5 分钟切回静态数据，站点照常跑

**现在卡在 M0 —— 6 个决策点 + Stripe 主体确认。你回一句「按推荐执行」，我再动代码。**
