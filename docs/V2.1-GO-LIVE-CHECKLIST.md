## 1. ⚠️ P0 阻塞：Stripe 不支持中国大陆主体

### 事实依据

我于 2026-09-03 抓取了 Stripe 官方注册地清单页 <https://stripe.com/global>，列出的可注册国家/地区为：

```
AU AT BE BR BG CI HR CY CZ DK EE FI FR DE GH GI GR HK HU KE LV LI LT LU
MY MT MX NL NZ NG NO PL PT RO SG SK SI ZA ES SE CH TH AE GB US
```

**其中没有 CN（中国大陆）**。页面底部还有一个专门的区块：

> "Is your business outside of a supported country/region?"
> Use Stripe Treasury with stablecoins to manage your money globally. **Payments not supported yet.**

### 为什么必须现在告诉你

你此前提到「我有大陆企业资质」——按上面的官方清单，大陆企业资质**不能开通 Stripe 收款**。网上有文章声称「Stripe 已支持中国大陆企业主体直接注册」，与官方清单矛盾，那些是 AI 生成的 SEO 内容，不可信。

按「禁无据声称」铁律，我不能默认这个前提成立就把支付上线。**代码照现有 Stripe 实现是好的，问题出在收款主体资格，不是代码。**

### 三个方案（需要你拍板）

| | 方案 A：境外主体开 Stripe | 方案 B：换 Paddle（MoR） | 方案 C：先不接在线支付 |
|---|---|---|---|
| **主体要求** | 需 HK / US / SG / 英国 等境外公司 | 接受大陆主体 | 无 |
| **一次性成本** | 注册费（HK 约 HK$2,200/年 BR + 注册费） | 0 | 0 |
| **周期** | 1–3 周（含 KYC） | 数天 | 0 |
| **代码改动** | **零**（现有实现直接可用） | M4 支付层重写（3 个路由 + `lib/stripe.ts`） | 零 |
| **费率** | Stripe 标准费率 | MoR 抽成高于 Stripe 直连（口径以 Paddle 官网 Pricing 为准，我未核实具体数字） | — |
| **代价** | 需境外银行账户、UBO 资料 | Paddle 是法定卖家，发票开给客户的是 Paddle | 会员只能停在 free 档（5 家/月） |

### 我的推荐：C 打底 + A 并行

1. **先按方案 C 上线**（本周就能做）：Supabase 全部功能（注册/登录/收藏/RFQ/Admin 后台）+ 会员软锁框架全部可用，收款继续走 `/custom-services` 询盘 + WhatsApp 线下成交。`CheckoutButton` 已有降级逻辑，Stripe 未配置时自动跳 `/custom-services`，不会显示坏按钮。
2. **同时你去办 HK 主体**（方案 A）：办下来后只需在 Cloudflare 填 3 个密钥 + 在 Stripe 建一个 $99/年价格，**零代码改动**即可开通支付。

这么做的好处：不浪费已写好的支付代码，也不被境外公司注册周期卡住整站上线。

## 2. Supabase 配置（与支付方案无关，现在就能做）

### 2.1 建项目并建表

1. <https://supabase.com> → New project（区域选 **Singapore**，离 Cloudflare 边缘近）
2. 左侧 **SQL Editor** → New query → 粘贴 `supabase/migrations/001_init.sql` 全部内容 → **Run**
3. 确认无报错。该脚本建 10 张表并开启 RLS：

   ```
   profiles  memberships  suppliers  supplier_capabilities  supplier_evidence
   saved_suppliers  profile_views  rfqs  rfq_matches  stripe_events
   ```

### 2.2 关掉邮箱验证（**部署前置，不做会废掉注册漏斗**）

**Authentication → Providers → Email → 关闭 "Confirm email"**

原因：开启时用户注册后必须先点验证邮件才能登录，而 Resend 域名未验证前发不出去 → 注册漏斗归零。

关掉的同时，`app/api/auth/signup/route.ts` 里的防枚举处理生效：Supabase 对已注册邮箱会直接抛错，内部错误码记 `email_in_use` 便于排日志，但返回给用户的文案是中性的「无法创建该账号」，不泄露该邮箱是否已注册。

### 2.3 取三个值

**Project Settings → API**：

| 变量 | 位置 | 是否公开 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL | 公开（进 bundle） |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon / public key | 公开（安全靠 RLS） |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key | **⚠️ 秘密，绕过全部 RLS** |

> `service_role` 只能用 `wrangler secret put` 写进 Workers，绝不写 `.env`，绝不加 `NEXT_PUBLIC_` 前缀。
> 自检：`grep -rn "SUPABASE_SERVICE_ROLE_KEY" --include="*.ts*" .` —— 除 `.env.example` 外任何地方命中即为安全事故。

### 2.4 迁移供应商数据

```bash
cd "F:/AI-验厂SEO网站"

# 第 1 步：只预览，不写入（默认行为，安全）
node --env-file-if-exists=.env scripts/seed-suppliers.mjs

# 第 2 步：确认预览无误后，显式加 --apply 才真正写入
```

- 幂等：`upsert(onConflict: slug)`，重复执行不产生重复数据

- 迁移后全部为 `access_tier = "public"`，付费分层由你在 Admin 后台按家调整

### 2.5 把自己提权为管理员

先注册一个账号（用你自己的邮箱），然后在 SQL Editor 执行：

```sql
UPDATE profiles SET role = 'admin' WHERE email = '你的邮箱@example.com';
```

之后 `/admin` 才会对你可见（非 admin 一律 404）。
